# คู่มืออาจารย์: SQL Quick Quiz

หน้าอาจารย์: **https://sqlquickquiz.vercel.app/admin** (เข้าสู่ระบบด้วย Google `pornthep.ro@up.ac.th`)

หน้าแรกมี 3 เมนู:
- **โจทย์**: สร้าง/แก้/เปิด/ปิด, ดูการส่ง, ให้คะแนน, ประกาศผล
- **จัดการนิสิต**: นำเข้า CSV, รีเซ็ตรหัส, ปิด/เปิดบัญชี
- **รายงานและสำรองข้อมูล**

## ก่อนเปิดเทอม (ครั้งเดียว)

1. **นำเข้ารายชื่อ:** **จัดการนิสิต** → **เลือกไฟล์ CSV**
   - คอลัมน์ `student_id, first_name, last_name, section` ดูตัวอย่างที่ `docs/students-template.csv`
   - ใน Excel ให้บันทึกแบบ “CSV UTF-8”
2. ดูตัวอย่างและแถวที่ผิด แล้วกด **ยืนยันนำเข้า**
   - รหัสใหม่จะได้รหัสผ่านเริ่มต้น = รหัสนิสิต
   - รหัสที่มีอยู่แล้วจะอัปเดตชื่อและตอนเรียน
3. **คาบแรก:** ให้นิสิตเข้าระบบ แล้วเปลี่ยนรหัสผ่านพร้อมกัน (เมนู **บัญชี** → **เปลี่ยนรหัสผ่าน**) แจกคู่มือนิสิต `docs/manual-student.md`
4. เตรียมโจทย์ล่วงหน้าได้ โจทย์ที่ยังไม่เปิด นิสิตจะไม่เห็น ตัวอย่างโจทย์ดูที่ `docs/problem-examples.md`

## ขั้นตอนใน 1 คาบ

### 1. ก่อนเริ่ม (5 นาที)
- เปิดหน้าอาจารย์ แล้วดูว่าหน้า **โจทย์** ขึ้น “อัปเดตอัตโนมัติ”
- ให้นิสิต**เข้าระบบก่อนเปิดโจทย์ 2–3 นาที**
  - ทั้งห้องกดพร้อมกันได้ ระบบรับได้ราว 30 คนทันที แล้วต่อเนื่อง 20 คน/วินาที (110 คนครบใน ~6 วินาที)
  - คนที่ต้องรอจะเห็น “กำลังรอคิว” แล้วระบบลองให้เอง

### 2. สร้างโจทย์ (ถ้ายังไม่ได้เตรียม)
**โจทย์** → **สร้างโจทย์ใหม่** แล้วกรอก:
- ชื่อโจทย์
- คำอธิบาย, โครงสร้างตาราง, ตัวอย่างผลลัพธ์ เป็น markdown (ตารางใช้ `| คอลัมน์ |`)
- คะแนนเต็ม (ค่าเริ่มต้น 10)
- **คำสั่งเฉลย (นิสิตไม่เห็น)** ไม่บังคับ แต่ระบบจะเตือนถ้าว่าง

กด **บันทึกโจทย์** ใช้ **คัดลอกโจทย์** ทำข้อใหม่จากข้อเดิมได้

### 3. เปิดรับคำตอบ
- กด **เปิดรับคำตอบ** ที่โจทย์ นิสิตเห็นโจทย์ทันทีโดยไม่ต้องรีเฟรช (ราว 1 วินาที)
- **เปิด/ปิดทีละข้อ ห่างกันสัก 1–2 วินาที** ยังไม่ได้ทดสอบกรณีกดหลายข้อในวินาทีเดียว

### 4. ติดตามการส่ง
เปิดหน้ารายละเอียดของโจทย์ (กดชื่อโจทย์):
- “ส่งแล้ว N คน · ยังไม่ส่ง M คน” และรายการผู้ส่งอัปเดตเองแบบ realtime
- รายชื่อคนที่ยังไม่ส่งอยู่ด้านล่าง กรองตามตอนเรียนได้
- **ตัวนับบนหน้านิสิต** อัปเดตทุก 5 วินาที (โหมด polling) ช้ากว่าหน้าอาจารย์ได้เล็กน้อย เป็นเรื่องปกติ

### 5. ปิดรับคำตอบ
- กด **ปิดรับคำตอบ** นิสิตเห็น “ปิดรับคำตอบแล้ว” ทันที
- ฐานข้อมูลปฏิเสธการส่งหลังปิดเสมอ แม้หน้าจอของนิสิตบางคนยังไม่อัปเดต

### 6. ให้คะแนน (ทำในคาบหรือหลังคาบก็ได้)
ในตารางผู้ส่ง แต่ละคำตอบมี 2 แถว (SQL อยู่แถวล่าง) ชี้ที่รหัสนิสิตเพื่อดูชื่อ/ตอน

| ปุ่มลัด | คะแนน |
| --- | --- |
| เต็ม | 100% |
| ดี | 80% |
| ครึ่ง | 50% |
| ปรับปรุง | 25% |
| ศูนย์ | 0% |

- กดปุ่มลัดแล้วบันทึกทันที หรือกรอกคะแนนเองแล้วกด **บันทึก**
- เขียนความเห็นได้ไม่เกิน 2,000 ตัว
- เรียงตารางตามลำดับ/รหัส/เวลา/คะแนนได้ และแบ่งหน้า 20 (เลือก 50/100/ทั้งหมดได้)

### 7. ประกาศผล
- กด **ประกาศผล** → **ประกาศเลย**
  - ถ้ายังให้คะแนนไม่ครบ ระบบจะเตือน ประกาศได้ แต่คนที่ยังไม่ได้คะแนนจะเห็น “รอตรวจ”
- นิสิตเห็นผลในแท็บ **ประวัติของฉัน**
- ได้ **ลิงก์หน้าอันดับ** (กด **คัดลอกลิงก์**) แชร์ให้ทั้งห้องได้
  - เรียงตามเวลาส่ง แสดงรหัสแบบปิดบางส่วนกับคะแนน ไม่มีชื่อ ไม่มี SQL
- แก้คะแนนหลังประกาศได้ นิสิตเห็นค่าล่าสุด ประกาศแล้วยกเลิกไม่ได้

### 8. หลังคาบ
- **รายงานและสำรองข้อมูล** → **สำรองข้อมูลทั้งหมด (zip)** เก็บไว้ทุกคาบ
  - แผนฟรีของ Supabase ไม่มีการกู้คืนย้อนเวลา ไฟล์นี้จึงเป็นสำเนาเดียวที่อาจารย์ถือเอง
- **ส่งออก CSV** ได้คะแนนรายคน × โจทย์ กรองช่วงวันที่และตอนได้ เปิดใน Excel ได้ภาษาไทยถูก

## งานจัดการนิสิต

| เรื่อง | ทำที่ **จัดการนิสิต** |
| --- | --- |
| ลืมรหัสผ่าน | **รีเซ็ตรหัส** → รหัสผ่านกลับเป็นรหัสนิสิต และแถบเตือนกลับมา |
| พักการใช้ / ถอน | **ปิดบัญชี** → เข้าระบบไม่ได้ทันที คะแนนเดิมยังอยู่ เปิดคืนได้ |
| นำเข้าผิดคน | ลบได้เฉพาะคนที่ยังไม่เคยส่ง ถ้าเคยส่งแล้วให้ปิดบัญชีแทน |

## แก้หรือลบโจทย์

- **แก้ได้แม้มีคนส่งแล้ว** (มีคำเตือน) แต่คะแนนเต็มต้องไม่ต่ำกว่าคะแนนที่ให้ไปแล้ว
- **ลบได้แม้มีคนส่งแล้ว:** ต้องพิมพ์ชื่อโจทย์ให้ตรงเพื่อยืนยัน ระบบจะลบคำตอบและคะแนนของข้อนั้นทั้งหมด**กู้คืนไม่ได้** ควรสำรองข้อมูลก่อน

## ข้อควรรู้เรื่องระบบ (แผนฟรี)

- **ว่างนาน 1 สัปดาห์ project หยุดเอง:** workflow `Supabase keep-alive` บน GitHub ป้องกันไว้ ทำงานทุก 3 วัน
  - ถ้าได้อีเมลว่า project ถูกพัก ให้กด **Restore** ใน Supabase Dashboard ก่อนคาบ
  - ถ้าได้อีเมลว่า GitHub ปิด workflow (repo ไม่มี commit 60 วัน) ให้กด **Enable** ใหม่
- **เปิดใช้พร้อมกันได้ไม่เกิน 200 การเชื่อมต่อ** (1 แท็บ = 1) อย่าจัด 2 ตอนเรียนใช้งานพร้อมกัน
- **ระหว่างคาบแรก ๆ** เปิด Supabase Dashboard → Reports → Realtime ดูไว้ได้

| อาการ | ทำอย่างไร |
| --- | --- |
| นิสิตบางคนไม่เห็นโจทย์ที่เปิด | ให้รีเฟรชหน้า |

| เว็บเปิดไม่ได้ทั้งห้อง | ดูอีเมลจาก Supabase ว่า project ถูกพักหรือไม่ แล้วกด Restore |
